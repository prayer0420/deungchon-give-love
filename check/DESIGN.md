# 체크 · 디자인 노트

## 참고한 것

오.AI.완의 「클로드 모션 그래픽 프롬프트 전문」(2026-10-10). 원래는 30~90초 설명 영상을 만드는 프롬프트이고, 원칙은 Anthropic Claude Code 디자인 총괄 메건 최의 작업 방식에서 왔습니다. 이번에는 결과물을 영상 대신 지금까지처럼 한 화면 스크롤 초대장으로 두고, 원칙만 옮겼습니다.

- 모양을 먼저, 다듬기는 마지막에: 하나의 생각(처음이어도 괜찮다)과 보는 사람의 머릿속 그림(걱정 목록)부터 정했습니다.
- 디자인 전에 질문 세 개: 누구를 위한 것인가, 무엇을 전하나, 이름이 필요한가. 답은 directions.html 맨 위에 있습니다.
- 빈손으로 시작하지 않기: 기획서 문구, 실제 날짜와 달력, 실제 등촌교회 건물 선, 기존 가면·선물 사진에 묶었습니다.
- 넓게 펼친 뒤 고르기: 방향 네 가지를 같은 다섯 박자로 그려 놓고 하나를 골랐습니다(directions.html).
- 절제가 취향: 바탕 하나, 강조색 하나, 글꼴 둘, 격자 하나.

## 이야기 (질문 → 모델 → 증명 → 반전 → 답)

- 질문: 많은 사람이 믿는 틀린 생각에서 시작합니다. 「교회는 처음이면 어색할 것 같죠?」 제목 카드가 아니라 그림(걱정 목록)으로 엽니다.
- 모델: 가장 작은 정확한 그림. 일정표 다섯 줄(날짜, 시간, 장소, 프로그램, 남은 시간)이 한 줄씩 나옵니다.
- 증명: 프로그램마다 원인과 결과를 화면에서 보여 줍니다. 무언극이 나오면 「성경, 교회 용어」가 지워지는 식입니다.
- 반전: 변수 하나(교회와의 거리)를 바꿔 봅니다. 처음이에요 · 오랜만이에요 · 다니고 있어요. 들어오는 동안 값이 차례로 바뀌고, 지워진 걱정은 그대로입니다. 직접 눌러 볼 수도 있습니다.
- 답: 첫 그림(목록)이 다시 크게 나오고, 이번에는 바르게 읽힙니다. 다음 행동 하나(「갈게요」)가 붙습니다.

## 화면 규칙

- 색: 미색 바탕 #f3efe8, 카드 #fffdf9, 글자 #1c1a17, 강조 군청 #2a3fcf. 군청 글씨는 바탕 대비 6.8:1, 흰 글씨는 군청 위에서 7.8:1입니다.
- 글꼴: 제목과 큰 숫자는 Hahmlet 700(현대적인 한글 세리프), 나머지는 IBM Plex Sans KR. 앞선 버전들(Wanted Sans, Pretendard)과 다른 결입니다.
- 색만으로 뜻을 전하지 않습니다. 지워진 걱정은 파란 줄, 체크 표시, 흐려진 글자, 파란 답 네 가지로 표시됩니다.
- 금지: 네온 빛, 3D 덩어리, 그라데이션 제목 카드, 떠다니는 입자, 지어낸 숫자.

## 움직임 규칙

- 움직임은 뜻을 나릅니다. 위에서 아래로 차례(일정표 줄), 원인과 결과(그림이 나온 뒤 걱정이 지워짐), 크기(목록이 작아져 위로 비켜남)를 보여 줄 때만 움직입니다.
- 한 번에 하나만 눈에 띄게 움직입니다. 단계 사이 순서: 나가기(0~0.32) → 그림 열기(0.3~0.78) → 글(0.48~0.98) → 걱정 지우기(0.66~0.97). 지우기가 마지막이라 도착하는 순간이 핵심 동작입니다.
- 같은 물체를 바꿔 씁니다. 목록은 처음부터 끝까지 한 개이고, 크기와 자리만 바뀝니다.
- 이징은 직접 만든 곡선(1 - (1 - t)^3.4)으로, 튕기지 않고 가라앉습니다.
- 글을 읽는 동안 화면은 멈춰 있습니다. 화면 전체 확대는 쓰지 않습니다(세 번째 버전에서 어지럽다는 의견).

## 렌더 계약

- 모든 프레임은 숫자 t 하나의 함수입니다. t는 스크롤 위치를 단계 단위로 센 값이고, 첫 화면에서는 t가 -1에서 0으로 1.5초 동안 흘러 인트로가 됩니다.
- TIMELINE 객체 하나가 단계마다 가르치는 것, 지우는 걱정, 움직임 구간, 소리 신호를 모두 들고 있습니다.
- window.seek(t)는 그 프레임을 바로 그립니다. 검증에서 같은 t를 두 번 그려 픽셀이 같은지 확인했습니다.
- 예외는 사람이 누른 것(반전 선택, 리듬 재생, 태그)과 실시간 남은 시간뿐입니다.

## 소리

- 기본은 꺼져 있고, 「소리 켜기」를 누르면 72 BPM 절차적 배경음(Web Audio)이 나옵니다. Dmaj9 → Bm9 → Gmaj9 → A6/9를 두 마디씩 부드러운 패드로 깔고, 1·3박에 짧은 음을 둡니다.
- 모티프 하나(D-F#-A 세 음)가 걱정이 지워질 때마다 다음 8분음표 박에 맞춰 돌아옵니다. 마지막 걱정(처음이어도 괜찮아요)과 「갈게요」에서는 한 음(D)이 더 붙습니다.
- 레벨은 30초 오프라인 렌더로 쟀습니다. 최고 -9.7 dBFS, 평균 -23.4 dBFS. 웹 배경음이라 영상 기준(-16 LUFS)보다 조용하게 두었습니다.

## 이번에 쓴 기법과 팁

1. 반응형 키프레임: 단계마다 CSS로 배치한 빈 자리(.slot)를 두고, 목록 높이를 두 크기(k=0, 1)로 재서 빈 자리에 넣은 뒤 위치를 읽습니다. 움직일 때는 그 자리들 사이를 섞기만 하면 되어서, 화면 크기가 바뀌어도 레이아웃은 CSS가, 움직임은 숫자가 맡습니다.
2. 크기 변화는 transform scale 대신 CSS 변수 --k로 패딩, 칸 높이, 글자 크기를 함께 바꿉니다. 글자가 흐려지지 않고 칸 안 배치가 무너지지 않습니다. 라벨에 nowrap을 주면 높이가 너비와 무관해져서 미리 잴 수 있습니다.
3. 스타일 쓰기는 값이 바뀔 때만 합니다(WeakMap 캐시). 매 프레임 paint를 불러도 멈춘 화면에서는 아무것도 쓰지 않아 가만히 있습니다.
4. 정해진 크기의 그림(일정표, 달력, 리듬 카드, 선택 버튼)은 .fit으로 자리에 맞게 줄이기만 하고 키우지는 않습니다. 작은 휴대폰에서도 넘치지 않습니다.
5. 사진은 아래에서 위로 여는 clip-path(inset)로, 나갈 때는 아래 가장자리가 올라가며 닫힙니다. 다 열린 뒤에는 clip-path를 none으로 돌려 태그처럼 바깥으로 나가는 요소를 자르지 않습니다.
6. 선 그림은 pathLength="1"과 stroke-dashoffset을 t로 직접 계산합니다. CSS 전환을 쓰지 않아서 뒤로 스크롤하면 거꾸로 지워집니다.
7. 소리 예약은 박자 격자에 맞춥니다. 앞으로 0.4초 안에 올 박만 미리 잡고, 끌 때는 버스(필터+게인)를 통째로 바꿔서 다시 켜도 이전 음이 겹치지 않습니다.
8. 검증 순서: 같은 프레임 두 번 비교 → 단계마다 정지 화면 → 겹침과 넘침 숫자 검사 → 오프라인 음량 측정. 고친 것은 전후 화면으로 확인했습니다(리듬 카드, 데스크톱 묶음).
